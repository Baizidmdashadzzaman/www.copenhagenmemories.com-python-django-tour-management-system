# Integration of Locally Trained Chatbot Model

This implementation plan outlines the steps to integrate the fine-tuned model located at [trained-models/model](file:///m:/PROJECT/www.copenhagenmemories.com/www.copenhagenmemories.com/trained-models/model) into the Django web application, enabling the frontend chat widget to communicate directly with our local model instead of the Gradio API proxy.

## User Review Required

> [!NOTE]
> **Performance and Memory Footprint:**
> The model (`opt-125m`) has a footprint of roughly 250MB (fp16) to 500MB (fp32). Loading it in PyTorch locally on a CPU may take a few seconds during the first request but will run completely locally on the server without relying on any external APIs.
>
> To prevent slowing down the Django development server's automatic restart cycle (auto-reloader), the model will be loaded **lazily** on the first incoming query and cached in memory for subsequent calls.

## Proposed Changes

---

### Backend Service (Django App)

We will modify [ai_views.py](file:///m:/PROJECT/www.copenhagenmemories.com/www.copenhagenmemories.com/Yourtourguide/ai_views.py) to load and execute the local model.

#### [MODIFY] [ai_views.py](file:///m:/PROJECT/www.copenhagenmemories.com/www.copenhagenmemories.com/Yourtourguide/ai_views.py)
- Import `transformers` (tokenizer, causal LM, and pipeline) and `torch`.
- Add a lazy loader helper `get_chatbot_pipeline()` that caches the model pipeline in memory and chooses `device=0` if a GPU is available, falling back to CPU (`device=-1`) otherwise.
- Include query normalization logic to correct typos, matching the pre-processing during model training.
- Update `ai_chat_proxy` view to format the query using the prompt template `User: <Question>\nCopenhagenMemories:`, query the model, extract the text generated by the model, and return it as JSON response.
